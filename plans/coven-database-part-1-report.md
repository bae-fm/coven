# coven-database, part 1

The database crate opens the database named by `StoreDir`, checks integrity once per open, uses WAL, and holds one writer under foundation's store lock. It reserves any idle connection from four read-only connections, waiting only when all four are occupied; a separate process can open read-only without taking that lock. Closing waits for active calls, closes the connections, and releases the lock. Every clone then reports `DbError::StoreClosed`.

The initial coven migration creates exactly `_coven_columns`, `_coven_rows`, `_coven_cells`, `_coven_lost`, `_coven_writes`, `_coven_uploads`, and `_coven_operations`. The schema holds generation history, cell setters and parents, lost values, and every removal rule. The round-trip test writes an actual `RowState`, closes and reopens the database, and reconstructs present values from a real `notes` table or removed values from `_coven_lost`. `_coven_cells` holds no value copy. A migration test changes the app value and checks the reconstructed state. The test encodes timestamps, had-read sets, parents, lost values, setters and replacement causes with coven-format’s snapshot codecs; no production merge adapter is introduced. Loss records name their target directly because an excluded write need not have an accepted generation.

Synced declarations include keys, audience sources, shared triggers, and file declarations. Opening validates all seventeen specified `SchemaError` cases. App SQL goes through the authorizer: internal tables are protected and trigger target violations identify both trigger and table. Shared guards are checked as required conjuncts, distinguishing SQL from comments, literals, CASE and BETWEEN expressions. `coven_applying()` returns false for app statements.

Every pending app migration runs in one transaction. Each migration is classified against its own before-and-after schema; declarations are checked against the final schema only, following §17.1. New indexes and triggers on a table created by the same migration are part of the addition. Failure rolls back the entire app run and its version. Transaction control and connection-setting changes are refused. SQLite's implicit rollback also ends the migration, even if app code catches the statement error.

## Owners and policy

`DatabaseBuilder::open_graph` is the composition root. `Database` is the retained root owner; its private state owns the writer, readers, and lock. Each private `DatabaseConnection` owns its rusqlite connection. `MigrationContext` borrows that owner for closed SQL work; `SqlTransaction` borrows it for rollback ownership. `ReaderLease` reserves an idle connection while borrowing the database owner and returns its slot on drop. No raw connection leaves these owners. Blocking calls retain the database until they finish; there is no long-lived background task requiring a lifetime-authority row.

Policy additions place database after format, separate database and storage in both directions, confine rusqlite and libsqlite3-sys to database, and identify the internal-table declaration macro. They register the composition root, root owner, connection capability and internal dependency, construction-only connection and lock, borrowed contexts, and transaction and reader tasks. `StoreDir::lock_exclusive` is registered as a scoped capability factory. Spawned blocking work is confined to the database owner file. Checker rules were not weakened; a fixture now preserves existing composition roots when adding its test root, and boundary tests cover rusqlite directly.

## Decisions where the spec leaves representation open

- `application_id` stores coven's internal version; `user_version` stores the app version. No extra metadata table is introduced. Each coven migration has its own transaction.
- Unsigned counters use eight-byte big-endian blobs; timestamps retain all 16 bytes. Metadata and lost-value blobs use the same unframed bytes as snapshot fields, preserving parents, replacement causes and removed-row values without SQLite coercion. Format exposes typed codecs sharing its existing binary primitives and validators.
- Independent keys require a text-capable UUID component and validate existing values as canonical lowercase RFC UUIDs of version 4 or 7. Integer rowid generation and key defaults are refused; manually supplied numeric components of derived keys remain possible under §8.5.
- Audience declarations retain both root and inheritance calls and refuse that combination with `TwoAudiences`. File schema checks require the named columns to exist; the spec does not prescribe SQLite storage classes for them.
- A migration that leaves the schema unchanged counts as an addition. Constraints, indexes and triggers belonging to a newly added table are part of that addition. Indexes, triggers and constraints added to existing tables, and new views, remain breaking changes.

The branch was rebased onto origin/main at 252e2590 and follows its amended table descriptions and error variants. Blocking-task panics resume with their original payload; unexpected cancellation panics. WAL refusal reports the selected mode. The settings read explicitly verifies that the directory is a store. No additional spec error requiring a stop was identified; the independent-key UUID check and classification of local-table changes remain unchanged, pending the user’s spec decisions. Write capture, write records, signing, uploads, merge application, removal-rule evaluation, general app read/live-query APIs, waiting-write conversion, files and sync are not implemented.

## Verification

`export PATH="$HOME/.elan/bin:$PATH"; next/scripts/check.sh` passed in full: formatting, Clippy with warnings denied, ownership/capability checks, documentation, production builds, both feature configurations of the workspace tests, the Lean proof and axiom checks, and the Rust/Lean differential test. The database suite has 49 tests, including cross-process reading, concurrent read connections, writer exclusion, damaged files, exact schema errors, authorization, lossless state storage, migration changes to app values, panic propagation, one integrity check per open, WAL refusal and migration rollback. Four new format tests compare field bytes with real snapshot records and reject malformed fields. `git diff --check` also passed.

The checks ran on macOS. Windows and Linux execution, power-loss injection, injected rollback/close failures, and the excluded behaviors above were not checked.
